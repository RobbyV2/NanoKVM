# Assistant: the chaice extension, native in NanoKVM

Date: 2026-09-24. Status: design approved in conversation, spec awaiting review.

## Goal

Re-implement the capability of the chaice browser extension
(`chaice/chaice/chaice-extension`) as a first-class NanoKVM feature. The user
presses Ctrl-Ctrl + a key on the desktop page; the device captures the target's
screen, sends it with any saved context images to an LLM, and the answer is
shown, copied, or placed in the FRQ box. The on-page UI is identical to the
extension's. The extension is the behavioural reference: where this spec is
silent, do what `content.js` / `llm.js` / `background.js` do.

## Decided in conversation

- LLM requests run **on the NanoKVM** (Go server), not in the browser. The API
  key never leaves the device.
- Request bodies are the provider-native ("raw") bodies `llm.js` builds,
  byte-for-byte in shape. Transport is direct or through the chaice relay
  (`chaice-server/relay/relay.ts`), unchanged protocol.
- A "show UI" toggle hides every on-page element while hotkeys keep working
  (the extension's `ui` setting).
- The on-page UI is identical to the extension's: no redesign.
- Real end-to-end test on the device at 192.168.8.210 via OTA, including one
  real OpenRouter call with images, key from `~/.config/tutor/openrouter.key`
  (read at test time, never committed or logged).

## Out of scope

- M5Stick display mirroring: `displayUrl`/`displayPass`, `/api/answer`,
  `/api/frq`, `/api/status`, `/api/ctx`, `/api/scroll`, `/api/clear`, and the
  D (wheel-scroll-to-display) and Q (clear display) hotkeys.
- `blockFullscreen` / `spoofFullscreenDimensions` (fs-guard), `disableConsole`
  (log-guard), and the extension's disguise name. On our own page there is
  nothing for these to act on.
- The popup (its buttons duplicate hotkeys; the settings tab replaces it).

## Settings

Stored server-side in `/etc/kvm/assistant.json` (mode 0600, same load/update/
atomic-write pattern as `service/mcp/config.go`). Survives OTA because it is
under `/etc/kvm`. Admin-only read/write.

| key | type | default | extension equivalent |
|---|---|---|---|
| enabled | bool | false | (new) master switch: hotkeys + UI exist only when on |
| ui | bool | true | `ui` |
| provider | `gemini` \| `openrouter` | openrouter | `provider` |
| geminiBaseUrl | string | `https://generativelanguage.googleapis.com/v1beta` | `geminiBaseUrl` |
| geminiModel, geminiApiKey | string | "" | same |
| geminiThinking | bool | false | same |
| thinkingBudget | int | 512 | same (stored as number) |
| orBaseUrl | string | `https://openrouter.ai/api/v1` | same |
| orModel, orApiKey | string | "" | same |
| orReasoning | bool | false | same |
| orReasoningEffort | `low`\|`medium`\|`high` | low | same |
| proxyUrl, proxyPass | string | "" | same (relay) |
| copyClipboard | bool | false | same |
| answerSel, contextSel, frqSel | bool | false | same |
| quadClickMCQ | bool | false | same |
| prompts | {universal, mcq, frq} strings | extension's `prompts.toml` | `prompts.toml` |

`GET /api/assistant/config` returns everything except the two API keys and
`proxyPass`, which are replaced by `hasGeminiApiKey`/`hasOrApiKey`/
`hasProxyPass` booleans. `POST /api/assistant/config` takes the same shape;
an absent or empty secret field leaves the stored secret unchanged, and an
explicit `clear*` flag removes it (the MCP/PicoClaw masking convention).

Per-browser state that the extension kept in page storage stays in the
browser's localStorage: FRQ box text (`lastFrqResponse`), FRQ box position and
size.

## Server: `server/service/assistant`

Files, each with one job:

- `config.go`: load/save/mask as above; `config_test.go`.
- `llm.go`: Go port of `llm.js`. `BuildConversation(cfg, turns, thinking *bool)
  -> Request{URL, Headers, Body}` and `ParseResponse(provider, data)`. Same
  URL construction, headers (`HTTP-Referer: https://github.com/chaice`,
  `X-Title: ChAIce` included), roles, part ordering, thinking/reasoning rules,
  attachment classification table and text-attachment formatting. Screenshot
  parts use `image/jpeg` because the device captures JPEG; everything else is
  unchanged. `llm_test.go` asserts bodies against fixtures generated by
  running `llm.js` itself under Node (`testdata/*.json`, generator script
  committed alongside).
- `transport.go`: port of `performApiRequest`: no proxy → direct; proxy →
  POST to `proxyUrl` with original headers + `X-Target-URL` + `X-Proxy-Pass`,
  300 s per attempt, 2 attempts 5 s apart, unwrap `X-Relay-Wrap: 1`
  (`{status, body}`), then direct fallback. Returns `{ok, status, data |
  bodyText, route}`. `transport_test.go` uses `httptest` for a fake relay and
  a fake provider.
- `capture.go`: full-resolution JPEG of the target via the existing
  `service/mcp/capture/kvm` backend; optional crop given a rect in source
  pixels (decode, crop, re-encode JPEG q=92). `capture_test.go` for crop math
  and bounds clamping.
- `contexts.go`: in-memory ordered list of context images (JPEG bytes),
  cleared on T and on server restart (the extension kept them per browser
  profile; per device is the KVM equivalent).
- `attachments.go`: files uploaded in settings, stored in
  `/etc/kvm/assistant/attachments/`, sent exactly as the extension sends its
  bundled `attachments/` folder (two-turn flow below). Size cap 20 MB total.
- `flows.go`: the ask flows from `content.js`:
  - MCQ / FRQ: prompt = universal + mcq|frq; images = contexts then the
    question screenshot. Without attachments: one turn. With attachments:
    turn 1 = question + images + "reply OK" with thinking forced off,
    assistant turn "OK", turn 2 = attachments + prompt + "Now answer the
    question above." (verbatim strings from `content.js`).
  - Custom (M): universal prompt + FRQ-box text + contexts, no screenshot.
  - Context (C): capture (optionally cropped), append to contexts.
- `handlers.go` + `server/router/assistant.go`, all behind `CheckToken()` +
  `RequireRole(admin)`:
  - `GET/POST /api/assistant/config`
  - `POST /api/assistant/ask` `{kind: "mcq"|"frq"|"custom", crop?: {x,y,w,h}, text?}` → `{answer, route}`
  - `POST /api/assistant/context` `{crop?}` → `{count}`; `DELETE /api/assistant/context` → `{count: 0}`; `GET /api/assistant/context` → `{count}`
  - `GET /api/assistant/screenshot` → `image/jpeg` (freeze overlay)
  - `POST /api/assistant/reasoning` `{direction: "up"|"down"}` → new level
    (applies the extension's ±512 budget / off→low→medium→high cycle
    server-side and persists it)
  - `GET/POST/DELETE /api/assistant/attachments`
- Errors use the server's `{code, msg, data}` envelope. No-answer (null parse)
  is a distinct code so the UI can show the yellow "no answer" state.

The feature does not take the HID control lease: it only reads the screen
and never types.

## Web

- `web/src/api/assistant.ts`: typed client for the endpoints above.
- `web/src/jotai/assistant.ts`: config atom (loaded once for admins on the
  desktop page), context count, busy flag.
- Settings: `web/src/pages/desktop/menu/settings/assistant/` registered as an
  admin tab in `settings/index.tsx`. Sections mirror `options.html`:
  enable + show UI; provider with Gemini / OpenRouter fields and reasoning;
  proxy; behaviour (clipboard, the three selection toggles, quad-click);
  prompts (three textareas, reset-to-default); attachments (upload/list/
  delete). i18n keys go in `en.ts` only (fallback covers the other 23).
- Desktop runtime: `web/src/pages/desktop/assistant/`, mounted in
  `desktop/index.tsx` only when `enabled` and the user is admin. Ports of the
  `content.js` pieces, kept as separate files:
  - `hotkeys.ts`: Ctrl-Ctrl prefix (two non-repeat Control keydowns within
    500 ms, left or right), then an action key matched on `e.code`. Window
    capture-phase listener so it runs before the desktop keyboard's
    document-bubble listener; on match `preventDefault` +
    `stopImmediatePropagation` on the keydown and the matching keyup, so
    the action key never reaches the target. Ctrl presses themselves still
    go to the target, as in the extension. Escape cancels selection. The
    listener is removed while a keyboard-lock source is held (settings
    modal, paste dialog, PicoClaw input), except for the FRQ box which
    takes its own lock while focused.
  - Keys: A, C, T, F, S, M, P, L, R, ArrowUp, ArrowDown, Escape. R reloads
    the page.
  - `quad-click.ts`: 4 clicks within 2 s on the screen triggers MCQ (when
    enabled).
  - `selection.tsx`: full-viewport overlay + dashed rectangle; converts the
    rectangle from CSS pixels on the `#screen` element to source-video
    pixels using the existing object-fit-contain geometry in
    `screen/geometry.ts`. With `ui` off it is `opacity:0` but works.
  - `status.tsx`: 2 px status bar with the extension's exact colours and 3 s
    reset, context count, the three dots (the display dot is dropped with
    the display feature).
  - `toast.tsx`: answer toast, first 40 words, 1.75 s fade.
  - `frq-box.tsx`: 340×120 draggable resizable contenteditable box, 500 ms
    autosave to localStorage, takes a keyboard-lock source while focused.
  - `freeze.tsx`: P fetches `/api/assistant/screenshot` and shows it as a
    full-screen `pointer-events:none` overlay; P again removes it.
  - `crop-lock.tsx`: L runs a selection and scales that region of `#screen`
    to fill the viewport via CSS transform; L again resets. Mouse
    coordinates keep working because the screen's own mapping reads the
    element's rendered rect.
  - `page-style.ts`: when `ui` is on, applies the extension's page CSS
    (hidden scrollbars, `#screen{height:100vh;object-fit:contain}`, white
    menu bar) and closes the menu bar once on load, as the extension does.
  - Inline styles and z-indices copied from `content.js`/`styles.css`.
- Clipboard copy on MCQ uses `navigator.clipboard.writeText` when the
  document has focus (secure context: the device serves HTTPS).

## Testing

- Go: unit tests above, run in the builder container (`make app` path; host
  Go tests of this package must not import cgo `common`, so `capture.go`
  takes the capture backend as an interface and tests pass a fake).
- Web: `tsc --noEmit`, existing test runner for `hotkeys.ts` (prefix timing,
  repeat rejection, keyup swallowing) and selection→source-pixel mapping.
- End-to-end on 192.168.8.210:
  1. `make release-build`, web build, `scripts/package.sh <next version>`;
     install through the web UI's offline update; confirm `/kvmapp/version`.
  2. Configure through the new settings tab with Playwright: OpenRouter, a
     vision-capable model, key from `~/.config/tutor/openrouter.key`.
  3. Put known content on the target screen (a question with a unique
     answer rendered as an image) and verify MCQ, FRQ, context (C then A
     uses both images), T, M, S, P, L, ↑/↓, Esc, quad-click, clipboard copy,
     `ui` off (nothing rendered, hotkeys still produce answers via
     clipboard), and that no action key reaches the target (checked via
     the target's own key log).
  4. Relay path: run `chaice-server/relay` on this machine with a password,
     point `proxyUrl` at it, repeat one ask, and confirm the route; then stop
     the relay and confirm the direct fallback.
